# Test Lanes

Context Panel maps every tracked file under `Tests/` to an intentional lane in
`Config/ContextPanelTestLanes.json`. The manifest is a fail-closed ownership
record: adding a test or fixture without classifying it causes the commit gate to
fail.

## Lane Boundaries

- `fast-local-python`: the focused Python contract tests included in the local
  commit gate.
- `routine-ci-python`: hermetic Python `unittest` files that use fixtures, fake
  clients, and temporary directories. They do not require credentials, signed
  artifacts, provider access, or devices.
- `routine-ci-swift`: the hermetic SwiftPM `ContextPanelCoreTests` target.
- `release-only`: credentialed or signed-artifact checks that run only in a
  trusted release context.
- `visual-evidence`: exact-build gallery or visual-review evidence. Simulator
  renders may satisfy shared-view evidence, but not actual-runtime requirements.
- `actual-runtime`: evidence from `/Applications/Context Panel.app` or physical
  devices under the runtime rules in `AGENTS.md`.
- `support-only`: fixtures and helpers that are consumed by tests but are never
  executed independently.

Do not move a test into a routine CI lane merely because its filename starts
with `test_`. Verify that it is hermetic first. Credentialed, signed-artifact,
device, Production CloudKit, App Store Connect, and canonical-runtime checks must
remain in their protected lanes.
Every file assigned to a manual protected lane must also have a non-empty entry
in `manualLaneJustifications`; this prevents a test from being silently parked
outside executable gates.

## Commands

Validate complete ownership:

```sh
python3 scripts/context-panel-test-lanes.py validate
```

Run the focused local Python lane with per-file timing:

```sh
python3 scripts/context-panel-test-lanes.py run --lane fast-local-python
```

Run the complementary routine CI Python lane with per-file timing:

```sh
python3 scripts/context-panel-test-lanes.py run --lane routine-ci-python
```

List the files in a safe lane:

```sh
python3 scripts/context-panel-test-lanes.py list \
  --lane routine-ci-python --safe
```

The commit gate runs the focused Python lane and times the complete Swift lane.
CI also runs the complementary routine Python lane. Reports are written under
`.build/test-lane-timings/` and uploaded by CI. They
contain repository-relative test paths, durations, exit status, source commit,
and bounded runner metadata such as OS, architecture, and image version; they do
not contain arbitrary environment values, credentials, command output, machine
names, or absolute checkout paths.

## JetBrains Inspection Preparation

The repository declares its worktree-local Python SDK preparation in
`.github/github.json`. Before a JetBrains inspection, the inspection helper uses
`uv` to create a Python 3.13 environment at `.venv` and generates the local
`.idea` project model with `Tests` marked as a test root. Both directories are
ignored and must be generated independently in each linked worktree.

This preparation exists only to provide semantic Python inspection for the
repository's validation scripts and tests. Context Panel is not a Python
package, so the preparation does not run dependency synchronization and does
not require a `pyproject.toml` or `uv.lock`.
